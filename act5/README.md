# 第三幕 · 校园日常

《我们的故事》第三幕。不是一条主线，是六个散在不同日子的课间小事：
一起办事、放学后的布告栏、校园寻物、楼梯口的两瓶水、课间猜人物、体育活动。
文件夹叫 `act5`，是因为它在工程里排在第四幕之后；故事里它是**第三幕**。
这个错位是历史原因，不改目录名了——改了两边的存档键和资源路径都得跟着动。

打开方式：完整流程从仓库根目录 `index.html` 的开始页进入；也可以直接用浏览器单独打开
`daily.html`（`file://` 就行，没有构建步骤、没有模块、不加载音频文件，所有声音都是
Web Audio 现场合成的）。

前后剧情另在 `narrative/`：从第四幕栏杆结尾进入心绪与由乃初见，返回本页玩日常；
六项日常完成后，目录和整章结果卡可进入由乃谈话的收尾，收尾最后一屏回到根目录开始页。
四个小游戏玩法文件不受该剧情层影响。

> **角色名**：朱里的闺蜜叫**由乃**。早期稿子和资源目录里直接写作「闺蜜」/ `friend`，
> 现在游戏内所有说话人、按钮、消息署名统一显示「由乃」；`friend` 只是资源与变量标识。

## 三、为什么走廊是横版一维

项目里所有学校场景素材都是正面平视的横版走廊（墙地分界在 y≈200）。
在这些走廊图上做俯视格子地图会和现有美术直接打架——图里根本没有「地面纵深」可以走。

所以「走路」只沿 x 轴，深度靠两件事假装出来：

1. 三个人站在**不同的 y** 上（G01 的站位是 `girl 218 / friend 224 / boy 230`），画的时候按 y 排序，
   互相穿过时看起来是前后错开，不是叠在一起。
2. `depthScale(y, 204, 244)` 给一点缩放（0.92–1.06）。

走位线定在 225 附近是算过的：再往下就站到画面最前沿，对白框一出来整个人就没了。

G04 是例外：那一场的球场不是走廊图，是 `ball.js` 用粉笔线程序画的梯形，
本身就有近大远小，所以 W / S 可以真的往纵深跑——但人还是同一套四方向帧，
只按 `scaleAt(d)` 缩放，不引入第二套美术。

## 四、四个小游戏

### 共用的主动互动层（F + 短反应）

原先四个游戏的互动几乎都是「走到点按 E → 读一段对白」，玩家一直在**回应场景**，
很少能自己起个头，角色也不会对他刚做的动作马上接一句。这一层统一补上：

- **`F`（或左下角那颗胶囊，触屏可点）= 玩家主动发起。** 章节壳统一把 `F` 路由到
  `D.poke()`，各游戏在 `start()` 里 `D.onPoke(handler)`，`dispose()` 里 `D.onPoke(null)`。
  输入框聚焦时 `core.js` 的 `typing()` 会先拦下，打汉字不会误触发。
- **`D.react(who, text, ms)` = 角色即时回应。** 左上角一句话就散的短反应：
  **不弹对白框、不触发 `dialog:start`、不冻结走位、不抢 E**，所以走路、接球、猜词都不断。
  两句连着发会排成一来一回。换场、收尾、退出时 `D.clearReact()` 清干净。
- **每个游戏的 F 含义不同，但都不改存档、不改成绩、不改结局。**

| | 胶囊 | 按 F 发生什么 | 角色还会对什么即时反应 |
|---|---|---|---|
| G01 | `F · 搭话` | 三句轮换（今天弄得完吗 / 要帮忙吗 / 还挺沉），她马上接一句 | 这一场改成原地做事，不再对走位反应 |
| G02 | `F · 自言自语` | 自己嘀咕一句，由乃回一句；**不吃「问问由乃」的三级提示次数** | 看完一处落一句「记一下。」、站久了「……先从哪儿看起。」 |
| G03 | `F · 抢答` | 把主持人没念完的话带过去，直接进题 | 手写出答案时「还能直接写出来啊。」 |
| G04 | `F · 喊一声` | 球在谁脚下谁回一句（带球时「看着呢」，球在对面时「你自己来拿」）；**不改球权、不改比分** | 抢断成功、被假动作晃过、射门进/偏都有短气泡 |

另加两段**可选插曲**，都不拦关：

- G02 找到卡之后「怎么还给她」三选一（递过去 / 放桌上 / 先喊她一声），
  只给收尾添第一句；**不选 6 秒后自动按默认往下走**。
- G03 六题之后「换你出题」，从三个词里挑一个，她俩马上接一句。
  不给分、不计时、不写存档，6 秒不选也会自己收尾。

### G01《一起去办事》

一张走廊图，三个站位：朱里在布告栏前，由乃在教室门口，我在右边搬箱子。
三个人各做各的，**原地做完**，不再从走廊走到楼梯口再走到楼上。

- **换人**：画面下方中段的三颗按钮（朱里 / 由乃 / 我），当前的人在做的角色亮着，
  另外两个变暗但继续播自己的待机动作；`Tab` 也能轮换。做完的人打勾。
- **朱里 · 贴通知**：按住空格把通知从手里推进布告栏的虚线框。纸在升，
  松手时正好在框里就贴好；没进框就翘一角掉回手里，`noticeMisses++`，再来一次。
- **由乃 · 数材料**：地上三摞纸，纸上印着号。首通顺序固定为 `[2,3,1]`，重玩会按种子洗牌，
  并保证和上一次不同。`A / D` 选一摞、`E` 拿起，或者直接点那一摞；按 1 → 2 → 3 拿。
  拿错不罚，`paperMisses++`，从头重数。
- **我 · 搬箱子**：按住空格从右边往楼梯口推。中途有门槛，箱子会卡住，
  按 `E` 抬一下才能过去；推到虚线落点松手才算放好。推过头（超过落点）箱子会滚回门槛前，
  `boxMisses++`，重推。首通往右边推；重玩的奇数轮会镜像成从左边楼梯口送，
  门槛点、落点、站位和楼梯口标签一起镜像。
- **三个人一起抬**：三件事都做完，三个人围到箱子边，站成一条线——朱里在左、我在中间、
  由乃在右，一起进入最后的合力抬箱。按住空格先蹲下抓住箱子（`pickup` 帧），
  再切到抬箱循环（`carry` 帧），箱子跟着离地；抬满 `CARRY.hold` 2.4 秒算抬起。
  箱子会自己晃，按 `A / D` 把合力条的指针压回中间；偏出去太多就放下重来，
  `carryMisses++`，抬升进度清零。
  触屏也能玩：按住画面是抬，点箱子左 / 右半边是 `A / D`。
  **没有失败态**：歪了只是放下重抬，抬满就过。
- **抬箱用的是已有素材，没有新画**：三张精灵表在 S3 加过帧，
  `boy_sheet_act5.png` 的弯腰 `25` / 抬箱 `43–46`，`girl_sheet_act5_carry.png` 的
  `27` / `50–53`，`friend_sheet_act5_carry.png` 的 `30` / `56–59`。
  `core.js` 的 `D.FRAMES` 把它们登记成 `pickup` / `carry`，`drawActor` 用 `a.pose`
  覆盖走 / 站帧；三个弯腰帧都朝左，所以站在箱子左边的朱里在弯腰段临时 `flip`。
- **三个操作都没有失败态**：做错只重来，`host.done()` 只在这一场结尾调用一次。
- **拾起以后还要走一段。** 三个人抬起箱子，以很慢的速度向楼梯口横移约 120px。
  途中一个路人（复用现有的 crowd）从对面走来，玩家在保持平衡的同时用 `W / S`
  调一条纵深线让开；碰到只是停一下重新抬起，不记失误、不失败，走到地方接原来的收尾对白。
  这一段用镜头平移兜住画面，世界坐标仍然走满 120px。
- **三个站位会互相帮一把，但只帮不罚。** 由乃的材料全对 → 朱里贴通知时纸的上升稳一倍
  （抖动减半），旁白会接一句「有人扶着就是不一样」；推箱全程没推过头 → 抬箱时箱子晃动 ×0.7。
  某一站做砸了，别的站就回到原难度，不会更难。
- **重玩会换一套参数。** 第 0 次（第一次玩、结果卡还没出过）永远用现行参数，
  保证第一次的体验和以前一样；之后按「第几次玩」（存在 `errandRuns` 里）换材料顺序、
  换虚线框的位置（三个候选位轮换）、奇偶轮换一条镜像路线。重玩不会是一模一样的第二次。
- 三个人都做完 → 停一拍 → 三个人一起走到箱子边 → 合力抬箱 → 收尾对白
  （「下节数学」），然后回目录。
- `F · 搭话` 随时可用，三句轮换；这一场不再对「掉头 / 站久了」做反应。

### G02《校园寻物》

周三中午，她的校园卡不见了。她在门口翻书包，你一个人出去找。

- **八处可看的东西，只有四处跟卡有关，而且哪四处每轮会变。** 其余的不是假线索，
  是真的、但没用的观察——找东西的时候本来就大部分白看。每轮的四处真线索、它们指向的地点、
  平面图上的正确路线都由「第几次玩」（`searchRuns`）决定；首通仍然是原来的窗台。
- **卡的位置有四个候选，每轮抽一个。** 楼梯口窗台（首通）/ 开水房刷卡机旁 / 布告栏下方 /
  楼梯拐角台阶。四处都合乎逻辑，线索链和正确路线都跟着换；自检会逐轮证明「仅凭这一轮的
  真线索可以唯一确定落点」。
- 线索分三种，**亲眼看见 / 我记得 / 我猜的**，在线索本里分栏列，样式也不同：

  | 类 | 说话方式 | 样式 |
  |---|---|---|
  | `see` | 「笔帽没盖」 | 实线 + 暖色 |
  | `remember` | 「她说过……」 | 实线 + 冷色 |
  | `guess` | 「……有人刚扶过。」「（这是猜的。也可能只是谁的手蹭到了。）」 | **虚线** + 灰紫 |

  猜的那条必须**在对话里就说破**，不能只在笔记本上贴个标签、嘴上说得跟亲眼看见一样。
  `check.cjs` 会断言这句话还在。

- **线索本能摊成一张地图。** 线索本底下多一行「在地图上想想」，打开二楼平面图
  （`assets/minigame/map_floor2.png`），上面七个可点地点：教室、窗台、饮水机、垃圾桶、
  招领处、监控、楼梯。点一个地点会摊出挑证据的面板；每个地点角上的数字是那儿挂着几条线索，
  其中有「我猜的」时角标画成虚紫。左上角的黄圈是**站号**：钉下的先后。
- **钉地点之前先挑证据。** 挑中的那句必须真的指向这个地点，否则只会说「这句说的是别的地方」——
  面板不关、线索不扣，可以接着读、接着试。线索用掉一条就少一条；取消一个地点，
  它那句证据会放回线索池。这样「我猜的」那条才真的是陷阱：它只能钉到楼梯，
  钉上去路线就多一站。
- **钉的先后就是线上的先后。** 钉到第二站，地图上就先画出玩家自己连的那条虚线；
  三站顺序不对，线会拐得别扭，点「看看这条线」会说「地方都对，可顺序不对」；
  错到第三次，才把「教室 → 接水 → 楼梯」的顺序说透。不点名、不扣次数、不拦路。
- **答案是她上午走过的三站：教室 → 饮水机 → 窗台。** 按这个先后钉中三站，
  地图上的线亮起来并开始流动，目标卡改成「卡多半在楼梯口的窗台上」。
  多钉、少钉都只说「多了一站 / 少了一站」，不点名是哪一站；拼错不罚、不拦、
  不扣提示次数，八处照样能走完。
  「我猜的」那条（扶手）钉在「楼梯」上，而答案里没有楼梯——把它也钉上就会多出一站；
  布告栏那张挂失通知也一样，它会把「招领处」带进来。两条都是真观察（一条是猜的），
  只是不在她上午走过的那条路上。
- **拼对和没拼对只差一句话。** 捡卡时的第二句，拼对过是「……果然在这儿。」，
  没拼对是「……还真是这儿。」；收尾和完成状态都不变。
  存档只加一个布尔 `searchRouteSolved`，记「拼出来过」，不记钉了几次、错了几次。

- **还能回教室门口问人。** 门缝和门牌看过之后，门口那条提示会变成「E · 问问朱里 / 由乃」：
  每人三个问题（最后一次刷卡是什么时候 / 上午去过开水房吗 / 卡套什么颜色……），答案以
  **「问到的」** 第四类线索进线索本（和看见 / 记得 / 猜的并列），也可以钉到平面图上。
  问几次都行、不扣分；问过关键问题之后，对应观察点的线索会换成印证版——「问到的」和
  「看到的」对得上，是这一节推理的满足感来源。提问不打断观察，看过的还能再看。
- **卡不在固定那个窗台了。** 四个候选落点都有合乎逻辑的线索链，首通仍是楼梯口窗台；
  重玩按游玩次换一个落点、一套真线索和一条路线。**不需要听完任何线索就能直接走到落点捡**，
  提前找到的话收尾会说「你怎么直接就找到了」，不拦路。
- **收尾会按步数说一句。** 记玩家这一局跨场景的次数（`steps`）：跑得少是「你心里有谱」，
  跑得多是「腿都跑细了吧你」，只换措辞，**不写存档、不记成绩**。
- 三级提示走「问问由乃」：她人不在场，发消息过来。一次比一次具体，
  第三次之后按钮变「问过了」：

  1. 你先别翻了。她上午就出去过一次，就一会儿。
  2. 出去那次是接水。接水得刷卡。
  3. 楼梯口那个窗台。你去看一眼就知道了。

- 收尾按「看了多少」分三种说法。三种都只说她怎么反应，不说她高不高兴。
- `F · 自言自语` 和「问问由乃」是**两套东西**：前者只是自己嘀咕，不给方向、不消耗提示次数。
  找到卡之后还能选「怎么还给她」，不选也会自己往下走。

### G03《课间猜人物》

**十八题 · 猜人物。** 动漫 / 游戏 / 电影各六题，每轮按类别各抽两题（共六题）出题；
主持人在由乃和朱里之间轮换。默认点选项，也可以直接打汉字。

- **题面是程序化剪影，不再受素材数量限制。** 每题左边 96×96 的剪影在 `<canvas id="wgSilCv">`
  上画出来：老九题仍用 `assets/silhouettes/` 的 PNG（画到离屏 canvas 再上蒙版），
  新九题改用一条 `fig` 数据（`body` 四种体型 + 1–2 件 `props` 道具路径 + `tint`），
  由 `wordgame.js` 里的 `WGMask` 用 Canvas 路径画成单色剪影。**加题不再需要加图片**：
  复制一条 `QUESTIONS`、填好答案/线索/选项、从二十件道具里拼个 `fig` 就能出题。
- **剪影会随着线索一层层变清楚。** 蒙版是随线索数推进的马赛克：一条线索 16px 格长、
  两条 10px、三条 5px、公布答案全清；每格取样偏移由题目 id 的哈希决定，同一题每次都一样。
  揭开时格长用 200ms 插值过去，不逐帧闪。
- **认人靠线索，不靠画功。** 三条线索是聊天口吻，并且分三类：外形（`look`）/ 经历（`story`）/
  台词（`quote`）。第一条固定展示，之后两条由玩家点选先听哪一类；不同的类别也会影响
  她俩在抢答窗里往哪个方向猜。剪影只是先有个形状可看，猜错不会因为「剪影不像」而冤枉。
- **每条线索后有 2.2 秒抢答窗。** 窗内答对得满分；窗一过，她俩先按线索类别报一句猜测
  （先猜错、被主持人纠正），玩家再答只算半分。「再给点提示」只在窗后可用，用掉这轮最多半分。
  三次机会用完就公布答案并清掉蒙版，照样往下走。
- **选项是四个真名**，正确答案的位置**每题不同**（`data-ans` 只给自动化脚本用），
  闭眼点第一个不会全对。同义词算对（`aliases` 里列了「蒙奇D路飞」「机器猫」这种），
  `norm()` 只去标点，不做模糊匹配。
- **打汉字时地图按键让路**，否则打字就把人走出去了（`core.js` 的 `typing()`）。
  手写答对会走和选项命中同一条路，只多一句「还能直接写出来啊」。
- **重玩会换一套题。** 每场按「第几次玩」做种子（`wordRuns`），三类各抽两题，不重复。
- **半场会跑题。** 第三题之后有人去接水，话题跑到那档停播的综艺上，聊两句再回来。
  这段没有题目、没有选项、不计分。
- 没有倒计时。答错就多给一条线索，线索用完直接公布答案，照样往下走。
- 成绩只改收尾那句话的措辞：六题全对是「全对。行啊你。」，四题以上「差不多吧。」，
  再少是「……下次让着你点。」。存档里只记 `wordGameCorrect` / `wordGameHints` / `wordRuns`，
  面板上不显示分数。
- `F · 抢答` 能把主持人没念完的话直接带过去。六题之后插一段「换你出题」，**现在做两轮**：
  先从「抢票 / 剧透 / 片尾曲」里挑一个词，再从三句里挑两句「像」的线索。第二轮她俩会
  排除第一轮已经出过、或第一轮猜错过的词；同样的误导只剩「犹豫半拍」，台词里会说
  「……上一轮我就栽在这儿，这次排除它」。挑剩的卡片会暗下去，**不给分、不计时**，
  不点也会自己往下走。

### G04《体育活动》

下周一放学后，楼前那块空地。这一场是**玩家一个人对由乃和朱里**，先进三个球。
球场画成俯视 2.5D：下面是近端、上面是远端，越远越窄；人物和球按纵深缩放。
玩家守下面的门、打上面的门，由乃和朱里反过来。玩家跑速 **96**，由乃 70，朱里 58——
三个人里最快，所以跑空位和回追都来得及。

**无球：跑位与抢断圈**

- `W / A / S / D` 四个方向都能走，斜着走会归一化，不会比直着快。
- 靠近持球的人按 `E` 打开**抢断圈**：护球人先护住上边或下边，整圈 0.9 秒；
  0.42 秒时可能突然换边（55%，换边会闪一下）。玩家用 `W` 打上、`S` 打下，
  触屏点人物的上半边 / 下半边也行。
  - 打中她**没护住**的那一边：断球成功。
  - 打中她护住的那一边：被挡回来，`stumble` 0.6 秒不能动，球还在她脚下。
  - 一直不选：0.9 秒后圈自己散掉，进 0.3 秒冷却。
- 抢断距离 30px，普通抢断冷却 0.42s。

**有球：带球与射门**

- `WASD` 带球（带球时速度 ×0.78；无球 96 不变，优势从「带球碾压」变成「无球跑位」）。
- 球不再粘在脚上：持球时球跟着人**朝向前方 0.05 纵深**的位置走，跟随速度有限，
  跑得越快球离脚越远；急转弯（0.2 秒内转向超过 100°）球向外多滑一点。球离脚超过 0.035 时，
  抢断距离从 20px 放宽到 26px——趟球失误只是小幅偏出，但上抢的人能利用那一瞬。
- `Shift`（或触屏拨球按钮）= 趟球：球向前拨出 0.16 纵深，自己 0.45 秒内加速到 1.15 倍，
  冷却 2.5 秒。拨球期间球不受控，守线的人可以拦截。这是玩家版的「过人」。
- 按住空格开始蓄力（0.9 秒到满）。
- 蓄力时人物站住，起脚先对准门中间；`A / D` 以每秒 1.05 弧度的速度**转射门角度**
  （脚下画一段虚线弧和度数，正数是往右），门线落点限制在 0.22–0.78 之间；
  `W / S` 把球挑高 / 压低（0.04–0.88），松手朝上面的门出脚。
  角度是按玩家站位换算的——离门越近，同样的角度在门线上偏得越多。
- 球是有高度的：飞过防守人时只要高过 0.38 就从他头顶过去；低于 0.38 且横向差在 0.055
  以内，会被挡下来。到门线时横向在 0.355–0.645 之间、高度不超过 0.62 才算进；
  偏出就是「偏了」，高过横梁就是「高了」。
- 蓄力太短（力度 < 0.16）算没踢上力，球慢慢滚开。
- **射门有散布，但看得见。** 出手落点 = 瞄准点 + 偏移，偏移由本局种子给出（可复现）：
  力量越大、离门越远、身前有防守人时越容易偏。蓄力时判定门前会画出半透明的扇形，
  范围就是这次可能的落点——风险先给你看，不做无预告的随机打偏。甜点在 6–8 成力。
- **被贴身压迫会走形。** 防守人站在玩家身前扇区、距离 < 26px 时，蓄力速度 ×0.7、散布更大；
  力度不到 0.25 出手必是踢呲。逼出「先摆脱 → 站稳 → 射门」的节奏。
- **中柱。** 落点贴着门柱（±0.008）且在门高内会弹出来，球变 loose，头顶气泡「中柱。」。
  死角收益最高，风险也最高。
- **电脑不会贴上来就断球。** 由乃 / 朱里进到 20px 内先抬手 0.32 秒：头顶一个收拢的圈和
  「伸脚」。这期间玩家跑开、把球射出去，或者球不在脚下了，这一下就落空。
  断球成功后由乃冷却 2.4 秒、朱里 3.0 秒。
- 开球站位改成有纵深的阵型：我 (0.50, 0.30)、由乃上抢位 (0.56, 0.55)、朱里守线位 (0.44, 0.80)，
  中路不再是空的。抢断保护按来源区分：刚断下球（抢断）有 2.2 / 2.4 秒喘息；开球只给 0.6 秒，
  只防贴脸，不让人抱着保护一路带。进球后由失球方开球。
- 触屏按钮跟着球权换文案：有球时「按住蓄力 / 射门」，无球时「点一下 / 抢断」。

**防守：一个上抢，一个守线**

- 由乃和朱里每帧按到球的距离分工：近的那个上抢，远的那个退到「球 → 远门」连线上守线
  （距门线 0.10 纵深，横向随球插值）。分工有 0.5 秒迟滞，不会原地来回换岗。
- 上抢不再瞄玩家当前位置，而是瞄**玩家位置 + 速度 × 0.35 秒**的提前点——直线带球会被
  提前截住，变向重新变得有意义。
- 朱里守门：玩家持球进入射程（纵深 ≥ 0.62）或球飞向远门时，她站到门线前 0.04，
  横向跟随玩家的瞄准落点，但慢半拍（120ms 延迟、±0.03 的固定预判误差）。
  玩家出脚瞬间她朝预测落点横扑（横向 0.11）：扑对方向、且是低球（离地 < 0.50）就扑出；
  扑错方向就够不到——**打她反方向、或者挑高球是正解**。她速度仍然最慢，靠站位不靠跑。

由乃：

- 带球往下面的门推进，速度 70；**每 1.2–2.0 秒做一次假动作**（`feintWindow` 0.35s，
  脚下亮一圈、头上一颗菱形）。窗口里按 `E` 会被她晃过去——玩家 `stumble` 0.6s 不能动，
  球还在她脚下；窗口外按 `E` 才会打开抢断圈。她每次拿球至少先做一次假动作再射，
  所以这个窗口一定会出现。
- 到门前先停一下，抬脚有 0.7 秒的「!」；射门命中率 0.75，没打正会偏出或挑高。
- 赢到两球之后开始给朱里做球（`scoreThem >= 2`）：不是放水，是她自己换了打法。
- 玩家领先两球时，她的上抢提前量从 0.35 秒提到 0.45 秒——不是放水，是她自己更急了。

朱里：

- 跑速 58，约等于玩家的 0.6 倍；带球更慢，射门前要抬脚 0.95 秒。
- 她起脚时 20% 踢空（`airKicks` 记下）、25% 交给更靠近球门的由乃，其余自己射，命中率 0.6。
- 她也会来抢，但慢、成功率低；作用是让场面不像一对一。
- 玩家领先两球时，她守门的预判误差从 ±0.03 收到 ±0.02；玩家落后两球时，她守线/守门会
  悄悄偏一侧 0.04，露出远角。都不说破，也不出任何提示文本。

比分：

- 左边「我」，右边「她们」，`scoreboard_{我}_{她们}.png` 只出现在 `#bgHud` 里。
- 先进三个球结束；玩家能赢，也能输。比分**不写存档、不进结果卡、不改任何关系走向**。
- 收尾赢的那句不庆祝，输的那句不检讨：「球停在中间，谁也没去捡」「风大」。

`F · 喊一声` 只让场上有人接话（带球时「看着呢」，球在对面时「你自己来拿」），
不改球权、不改比分。抢断、被晃、进球、射偏都有短气泡，**不弹完整对白框**。

球场是程序画的：水泥地、教学楼墙、梯形粉笔线、中圈、禁区、两端的球门（正面网 + 门框），
近大远小。球用 `assets/minigame/ball_sheet.png` 的四帧，带地面影子和飞行轨迹；
蓄力时有落点圈和一条弧线预览，抢断圈画在护球人脚下，上下两侧标着 `W · 上` / `S · 下`。
这一场不再加载 `field_overlay.png` / `goal_frame.png` / `fx_goal.png`，进球闪光是代码画的。

## 五、五条原则落在哪儿

| 原则 | 落实方式 |
|---|---|
| 人物首先是生活中的人 | 卡丢了要先跑食堂、由乃说「我坐她旁边，天天听她提」——先有生活，才有别的 |
| 不是每个小游戏都要制造心动 | G02 全程她俩在门口等，收尾只到「谢谢」；G01 结尾是「下节数学」；G04 结尾是「上课铃还没响」 |
| 由乃不能每次出现都起哄 | 她在 G01 一起走、在 G03 主持、在 G04 只是踢球和捡球、在 G02 人根本不在场（只发消息）。`check.cjs` 断言她在一场里的台词不超过一半 |
| 不按小游戏成绩决定感情走向 | 四个游戏都没有分数影响；G03 的成绩只改一句台词的措辞，G04 的比分只活在这一场，不写存档、不进对白 |
| 尊重真实记忆 | 物品、规则、台词、地点都是可替换的示例，换掉不影响结构 |

后来补的整层主动互动也没有破这五条：`F` 和四场的即时反应**都不写存档、不计成绩、
不改结局**。G02「怎么还给她」只给收尾添第一句，G03「换你出题」只是自己主持一小段、
不进题库也不记成绩，
G04「喊一声」只让场上的人接一句话。互动性加在「那段时间里发生过什么」这一层，
没有加到「她因而怎样」那一层——玩家能多起个头，但拿不到任何形式的回报数值。

存档只记「做过什么」：`errandCompleted`、`searchCompleted`、`searchClues`、`searchHints`、
`searchRouteSolved`、`wordGameCompleted`、`wordGameCorrect`、`wordGameHints`、
`ballGameCompleted`、`chapterDailyDone`，以及各场「第几次玩」的模块内计数
`errandRuns`、`searchRuns`、`wordRuns`（G04 不按次数变参数，不记）。
**没有任何一个数字代表「她有多喜欢你」**；G04 的比分也不在其中。
`check.cjs` 会扫掉注释后检查正文里不出现「好感度 / 心动值 / 认可度 / 喜欢你」。

## 七、自检

```
node act5/tools/check.cjs       # 静态 + 四个游戏各走一遍（?hub=1 从目录进）
node act5/tools/playall.cjs     # ?auto=1 自动时间线整链路
```

- **静态**：三张精灵表尺寸与帧数、`.face` 的 `background-size`、脚本无 ES module 语法、
  题库自洽（至少 5 题、答案在选项里、位置不许全在第一格）、
  G02 场景连线对称；G01 只剩一个场景，`active` / `switchTo` / `postNotice` / `countPapers` /
  `carryBox` 齐全、`Tab` 换人、`host.done()` 只一次、换人条 `#erTags` 三个 `data-who`、
  一起抬箱的 `startCarry / updateCarry / dropCarry / syncCarryTrio` 与 `CARRY` 参数、
  已有弯腰 / 抬箱帧（`setCarryPose`、`carry.rise`、朱里 `flip`）和章节壳里的三张精灵表；
  G02 线索分类齐全且「猜的」在对话里说破、
  可看点 6–8 处、由乃台词占比、文案红线；

## 八、踩过的坑

1. **换场景那句旁白不是立刻弹的。** 它要等淡入结束（约 0.5 秒）才出来。
   自检里如果在场景刚换就往下走，人物被冻在原地，`walk` 第一圈就退出，位置一步没动。
   现在用 `approach()`：先确保对白读完再走，被打断就补一次。

2. **`extras` 是每个场景都画的。** 朱里和由乃站在走廊门口，玩家上楼时她俩也跟着出现在楼梯口。
   必须在 `update()` 里按场景关掉（`hidden`），不能只靠初始位置。

3. **线索本面板太矮会露馅。** 下沿正好卡在她们脚踝上面，背景里露出两双鞋，像画错了。
   面板加了 `min-height`，按钮用 `margin-top: auto` 钉在底部，中间空出来的就当本子还没写满。

4. **换精灵表忘了改 `.face` 的宽度**（见第六节）。这是真踩过的：v2 换图之后三个头像全成了小人。

5. **互动点只建一次。** 每帧新建对象的话 `used` 标记会跟着丢，同一个点能反复触发。

6. **Tab 要拦，也要接住。** 不 `preventDefault` 的话焦点会跑走，接着按空格就在点按钮了。
   已加进 `core.js` 的 `BLOCK`；G01 在 `press("Tab")` 里轮换 `active`。点过换人按钮后
   记得 `blur()`，否则接着按空格 / 回车会再点一次那颗按钮。

7. **`#fade` 盖在所有面板上面。** 猜词面板一开就是全黑——因为上一段结束时 fade 停在 1。
   面板启动时先 `await D.fadeTo(0, 320)`。

8. **打汉字时人物乱走。** `keydown` 里先判断 `document.activeElement` 是不是输入框，
   是就直接 return，连 `preventDefault` 都不做（不然输入法候选框会出问题）。

9. **G04 换模型时，旧状态机不能只删一半。** 这一场从「传接 9 次」改成「先进 3 球」，
   又从横版一维改成俯视 2.5D；旧的 `target / rally / misses / breather / shiftPositions`、
   只沿 x 轴判距离的抢断、力度绿区那套都失效。自检也要同步删掉那些断言，
   否则会一边跑新球赛一边等永远不会再来的 `rally`。现在静态检查只认
   `goalsToWin`、俯视梯形参数、W/S 纵深轴、`aimX / aimZ`、抢断圈、跑速层级和存档里没有比分。

10. **测试脚本不能「干等玩家拿球」，也不能按一维跑位写。** 现在的 bot 要自己跑位：
    没球时追持球人，近身按 E 开抢断圈，等护边定下来后用 W/S 打另一边；
    有球时往远处带，到 d ≥ 0.80 按住空格 + W 蓄力再射；球滚开就去捡。
    跟人时按屏幕坐标（sx/sy）算方向、留 5px 死区，不能再用固定 x 目标位。
    另外，开球后电脑几秒就能进一球，进球会切 1.5 秒的 `goalPause`；
    跑位探针要先等 `state === "play"`，并在按住期间每 60ms 取一次快照，
    只拿 play 状态的快照判断——被进球打断不算按键失灵。

11. **收尾那一下的记分牌。** 最后一球进门后停在 `goalPause`，`syncHud()` 把记分牌刷成终局；
    `finish()` 只把球放回中间、收起按钮，**不重置比分**，等 `dispose()` 再收掉整块 HUD。

12. **章节壳从来没调用过 `dispose()`。** `runGame()` 只 `resolve()`，于是 G04 的
    HUD 一直挂在目录页和结果卡上方。现在在 `currentResolve` 里统一调
    `game.dispose()`；`check.cjs` 静态和浏览器各有一条断言看着。

13. **收尾截图拍得太早。** 目标卡是 0.25s CSS 淡出、目录是 rAF + 淡入，截图卡在半透明帧，
    看起来像「目标卡没撤」「目录空白」。拍之前等 340 / 380ms，别去改逻辑。

14. **球赛的两处遮挡。** 力度条说明字原来在条上方，正好压住球和男主的腿——
    挪到条下方、缩到 8px、加半透明底；气泡原来挂得老高，像贴在墙上的牌子——
    y 从 `-30` 改到 `-20`，收尾时再 `bubbles = []` 清掉「这边」，
    免得跟「谁也没去捡」打架。

15. **G01 三人同行会「躲着主角走」。** `trio.js` 原来用
    `boy.x - boy.dir * slots` 算「身后」，主角一转身目标位就跳到他另一侧，
    两人立刻掉头迎面穿过他——主角往右、她俩往左跑；挤到边界后 `sep = 12`
    还让两人对推顶死，跟主角越离越远。改成：目标位在另一侧时**不许横穿**，
    慢半拍（`lagRatio = 0.7`）同向跟着，等主角自己走过去再恢复跟随；
    两个目标位天然差 46，删掉会互顶的 `sep`。
    顺带清掉 `leadTo / onLag` 那段判定第一帧就把自己取消、从未生效的死路径。
    S3 之后 G01 改成三个固定站位，这段跟随不再上场；`trio.js` 现在只提供三个 actor、
    按 y 排序绘制和深度缩放，`check.cjs` 里「往左 → 往右」的掉头测试也一起拿掉了。

16. **短反应是排队播的，不是后来者覆盖前面的。** `D.react()` 把句子放进 `react.queue`，
    一条播完才轮到下一条。两句挨得很近时（比如上一条场景反应还没散就按 `F`），
    「一来一回」会排在它后面；自检原先只等 240ms 就断言，误报成「按 F 没反应」。
    改成在 `runBrowser()` 里监听 `DAILY.on("react")` 记 `window.__reactLog`，按 F 之后
    从当时的日志长度往后找，等到真正那两句出现（最多 6.5s）再判。
    临时冒烟脚本里 `reactStats().queued` 多出来的那一条，也查清是站着太久的
    「……不走吗？」而不是重复触发。

17. **即时反应和 F 要共用冷却。** 场景短反应如果跟玩家刚搭的话挤在一起，
    左上角会连刷三句，看着像卡了。G01 的掉头 / 站久反应在 S3 里拿掉了，
    现在只剩 `poke()` 自己的 0.9s 节流；G02 / G03 / G04 也各有 0.9–1.3s 节流。
    另外 `core.js` 的 `typing()` 拦输入框，G03 打汉字时按 F 不会抢答。

18. **插曲不能让脚本「等超时」混过去。** G02「怎么还给她」、G03「换你出题」都会
    在 6 秒后自动收尾，整链路脚本要是只等下一状态，等于这两块面板一次都没被点过。
    `playall.cjs` 现在在安全状态里显式点 `data-i="1"` 和第三个词；
    `check.cjs` 再分别验「点一次」和「不点也能自己往下走」两条路。

19. **G04 的 `F` 不再改球路。** 旧版按 F 会强制下一脚传球改道；新球赛里球权每秒都在变，
    F 再去改球路会和抢断/射门打架。现在 `callOut()` 只让场上有人接话，静态检查扫它
    里面不许出现 `ball.owner =` / `score* =` / `D.persist`。

20. **共用 UI 得在每场进出时都收干净。** 四块新面板分属不同游戏，章节壳统一调
    `dispose()`；但 `D.react` 的队列是全局的，换场不清就会把上一场的「这边」
    带到下一场开头。每场 `start()` 和 `dispose()` 都调 `D.clearReact()` +
    `D.reactHint(false)`，回目录后再按 F 不许触发上一场——静态和浏览器各有一条断言盯着。
    扩展静态检查时还漏声明过 `const shell = read("shell.js")`，属于同一批改动里的小坑。

21. **假动作窗口会被自己的射门吞掉。** 由乃到门前时，如果先判起脚、再判假动作，
    `startWindup()` 会把 `feintT` 清零，玩家永远等不到窗口。现在每次拿球记
    `yunoFeinted = false`，至少做完一次假动作才允许起脚；起脚前再判一次 `feintT <= 0`。

22. **挡射门只算「前面」的人，还要看高度。** 早期按 x 判定，站在球门里的由乃 / 朱里也能把
    已经过线的球挡出来。改成 2.5D 后按纵深穿越判定，而且只算站在射手前面的人
    （往远门打时 `a.d > shot.d0 + 0.015`）——贴着射手身后的人不能算封堵，否则一抬脚就被自己人挡下。
    球在穿越那一刻高于 `blockHeight`（0.38）会从头顶过去；低于它且横向差在 0.055 以内才算挡到。

23. **跟人的测试不能用固定目标位。** 「站在她右边 18px」在她往左跑时会先把玩家往右带一步，
    正好错过 0.35s 的假动作窗口。改成按屏幕距离：超过 22px 朝她跑，22px 内停下按 E；
    抢断圈开了就等 `duelT >= 0.5`（护边已经定下来）再按另一边，不能一直贴着她等。

24. **比分只活在这一场。** `scoreboard_*` 只出现在 `#bgHud`；`D.persist` 的参数里只有
    `ballGameCompleted`，`check.cjs` 扫 persist 参数和 store 的 key，杜绝把比分 / 胜负
    写进存档或结果卡。

25. **猜词题库和自检硬编码绑死。** `check.cjs` 里写死 `["粉笔","课表","晚自习"]`、
    循环 3 次，`playall.cjs` 点第一个选项；题库一换，自检要么假通过要么直接崩。
    现在题数从 `current.rounds` 读、答案靠选项上的 `data-ans="1"` 定位，
    静态检查另加一条「正确答案不许全放第一格」。

26. **「站着等由乃反抢」不能当测试前提。** 朱里也会伸脚，抢断是谁先碰上是随机的；
    朱里拿到球后由乃会退到她身后补位，玩家站着不动可能十几秒都轮不到她。
    现在自检和整链路都不等电脑送球：没球时主动贴上去按 `E` 开抢断圈，
    等护边定下来（`duelT >= 0.5`）打另一边；拿到球再自己带、自己射。
    拿球时机可控，不会被「谁先伸脚」的随机性拖住。

27. **按住类操作没有 keyup 路由，只能自己轮询 `D.keys`。** 章节壳只把 keydown 交给
    `press()`，没有 keyup 回调。「按住空格把纸推进框 / 推箱子」都在 `update()` 里读
    `D.keys[" "]`，松手的那一帧再判定；纸的落框区间由 `NOTICE_BAND` 从 y 反算，
    自检用 `waitForFunction` 等到区间里再松手，比 sleep 稳。

28. **门槛判定别写成「抬着才能走」。** 第一版是 `canPass = lifted || x < thr - 3`，
    箱子抬过门槛后自动放下，`x < thr - 3` 已经不成立，于是永远推不到落点。
    正解是只拦「还没跨过去」的那一段：`!lifted && thr - 3 <= x < thr + 2`。
    另外推过头的回滚是 0.9s 的补间，自检要等 `boxX <= thr - 6` 再断言；
    在 `boxX <= thr` 那一刻读到的是滚到一半的位置，会误报「没滚回来」。

29. **黑场里念串场旁白，玩家只看见黑屏。** `#fade` 是 `daily.html` 的靠后子元素，
    没有 z-index，会盖住 `.dlg`。自动时间线原来先 `fadeTo(1)` 再 `D.lines()`，
    台词其实在黑场下面，只是脚本按 E 能过去。现在每次跨日都先压黑，让 `#dayCard`
    盖在黑场上（它排在 `#fade` 后面并带 `z-index: 20`），日期卡退场后：
    周一补一句站位提示再交给 G01，其余三天直接交给游戏自己的日期开场。
    `D.audio.bell()` 补了铃：周一开场一次、周五下课后一次；其余跳切不硬塞声音。
    默认进入就是校园目录；`daily.html?hub=1` 会把目录展开，方便单场重玩或清存档，
    `?auto=1` 才走旧的自动时间线。

30. **射门方向要按「角度」调，不能只推门线落点。** 直接给 `aimX` 加固定速度，
    离门近时左右横移快、离门远时慢，手感不一致，玩家也不知道自己在转多少度。
    现在按下空格先把角度对准门中心，`A / D` 改的是脚下到门线的角度（1.05 弧度/秒），
    再由 `aimXFor()` 换算落点；顶到门柱外侧时用 `aimAngFor()` 把角度收回。
    `aimX` 仍留着给落点圈和自检用，但自检要同时断言 `aimAng` 和它的方向。
    电脑抢断也一样：贴上来就立刻得手等于没有操作空间，改成 20px 内先抬手 0.32 秒，
    玩家跑开或把球射出去就落空；断球后冷却拉长，开球时两个人退到两侧，
    中间留出带球的那一步。
